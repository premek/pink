# CLAUDE.md
Guidance to Claude when working with this repository.

## Code Style
Minimal layers of indirection but properly structured.
Prefer direct, obvious code over clever patterns.
Short functions with meaningful names, descriptive names for variables (no need to keep them extra short).
Prefer designs that are easier to reason about during development over ones that minimize data storage.
Parser is faithful: it produces an AST that reflects the source text as-is. Normalization (trimming whitespace, coercing values, etc.) belongs in the runtime or output layer, not the parser.

## Project Overview

**Pink** is a Lua implementation of the [Ink scripting language](https://github.com/inkle/ink) — a language 
for writing interactive branching narratives.

See [`docs/ink-language.md`](docs/ink-language.md) for a condensed Ink syntax reference.

## Workflow

### Code Navigation

Always prefer using LSP (via the `LSP` tool) over `grep` or `sed` for navigating Lua code. `lua-language-server` is installed and configured.

Prefer LSP over Grep/Glob/Read for code navigation:
- `goToDefinition` / `goToImplementation` to jump to source
- `findReferences` to see all usages across the codebase
- `workspaceSymbol` to find where something is defined
- `documentSymbol` to list all symbols in a file
- `hover` for type info without reading the file
- `incomingCalls` / `outgoingCalls` for call hierarchy
- etc.

Before renaming or changing a function signature, use `findReferences` to find all call sites first.

Use Grep/Glob only for text/pattern searches (comments, strings, config values) where LSP doesn't help.

After writing or editing code, check LSP diagnostics before moving on. Fix any type errors or missing imports immediately.

### Formatting, Linting

After each change:
```bash
stylua pink-cli pink/*.lua test/*.lua
luacheck --codes -q .
```

When a line-length warning hits a comment, split the comment across two lines — never truncate or delete content to make it fit.

### Debugging

Do not run `pink-cli format` for AST inspection or debugging — the formatter is not stable. Use temporary debug prints or LSP instead.

### Review
Before commit, look at the uncommitted changes and check if anything was missed.
Also review from high level perspective and readability.

### Running Tests

Run `stylua` before running tests.

```bash
./test/test.sh              # Run all tests, including linting
./test/test.sh I129         # Run a single test by name
./test/test.sh "W1.3.*"     # Run tests matching a pattern
LUAS="lua5.1 lua5.3 lua5.4 luajit" ./test/test.sh   # Run against multiple Lua versions
```

**Zero regressions policy:** a change is only acceptable if no previously-passing test starts failing.

Always compare against the baseline. Use separate commands — never chain with `&&` as test failures would skip the stash pop:
```bash
git stash
./test/test.sh 2>&1 > /tmp/baseline
git stash pop
./test/test.sh 2>&1 > /tmp/current
diff /tmp/baseline /tmp/current
```
Fix all newly failing tests before declaring the change done.

**Never use `&&` to chain `./test/test.sh` with anything** (including `diff`). The test script exits non-zero when any test fails, so `&&` silently skips the subsequent command — the diff never runs and regressions go undetected. Always use separate commands or `;`.

### Test Structure

Each test case in `test/runtime/{Name}/` contains:
- `story.ink` — Input story
- `input.txt` — Choice sequence (one per line)
- `transcript.txt` — Expected output (stdout)

`X*` tests cover Pink extensions and improvements incompatible with inklecate; they run without `--compat` and may include `stderr.txt`, `stderr_grep.txt`, and/or `stderr_stdout.txt`. See [`docs/testing.md`](docs/testing.md) for details.

To add a test, create a directory and run `./test/test.sh {Name}` (See [`docs/testing.md`](docs/testing.md)).

Never edit expected output (`transcript.txt`). 
Transcripts are generated by inklecate and represent correct Ink behavior. When Pink and transcript diverge, fix Pink — never update the transcript to match Pink's output.

To regenerate transcripts after changing a story: `test/runtime/regenerate.sh` (regenerates all W* tests).

Tests using any random output must use `~SEED_RANDOM(n)`. Lua 5.3 and C# (inklecate) use different RNGs — the same seed often produces different output. Use the search script to find a seed where both agree:
```bash
./test/runtime/seed_search.sh TESTNAME
```
This creates `setup.ink` (with the seed + `INCLUDE story.ink`) and regenerates `transcript.txt` automatically. See `test/runtime/I106/setup.ink` as an example of what `setup.ink` looks like.

API tests in `test/api.lua`.

## Naming Conventions

- `camelCase` for all Lua variables, locals, and functions
- `UPPER_SNAKE_CASE` only for Ink built-in function names (`FLOOR`, `RANDOM`, `LIST_ALL`, etc.)
- `_prefix` for intentionally unused variables (`_debug`, `_ctx`, `_node`)
- Single-letter locals are fine for short-lived values (`n`, `s`, `e`, `p`)

## Architecture

Pipeline:
```
.ink file → Parser → AST → Compiler → Runtime → Story API
```

### Core Modules (`pink/`)

- **parser.lua** — Lexical and syntactic analysis; converts Ink text to AST
- **compiler.lua** — Static phase; builds knot map, registers vars/consts/lists/functions, resolves initial values; called once before runtime starts
- **runtime.lua** — Execution engine; interprets AST nodes, manages story state and control flow
- **builtins.lua** — Built-in Ink functions (`FLOOR`, `RANDOM`, `CHOICE_COUNT`, `READ_COUNT`, etc.); wrapped in a factory that receives `getEnv`/`getChoices` deps
- **list_definitions.lua** — List schema registry; tracks element names, values, and definitions
- **output_buffer.lua** — Output buffering; handles glue/trim/newline logic before returning lines; factory function (`newOutputBuffer()`), one instance per story
- **story.lua** — Minimal story state constructor (`globalTags`, `state`, `variablesState`, `canContinue`)
- **formatter.lua** — Reverse compilation: AST → formatted Ink text
- **logging.lua** — Debug logging and error utilities
- **node.lua** — Value and AST node constructors + type helpers (`node.int`, `node.is`, `node.output`, etc.)
- **includes.lua** — Resolves `INCLUDE` directives by recursively parsing included files; called from `pink.lua`
- **path.lua** — Path helpers for visit-count and turn-tracking lookup keys
- **random.lua** — Park-Miller LCG; deterministic RNG portable across Lua versions; used by `SEED_RANDOM`
- **stack.lua** — Generic stack; used for the callstack

### Entry Points

- **`pink/pink.lua`** — Main module: resolves INCLUDEs, calls parser, calls runtime; returns story
- **`pink-cli`** — CLI: `pink-cli [-v] [format] game.ink`

### Key Data Structures

**env** — nested hash tables; `_parent` chain for scope, `_children` subtables for knot.stitch paths. Root env holds builtins + all globals.

**knots** — `{[name]={tree,params}, [name][stitch]={tree,pointer}}` — jump table built by compiler. `noKnot` (a module-level empty table) is the sentinel key for top-level content.

**callstack** — `[{tree, pointer, fn, env}]` frames. `fn='fn'` marks function calls (vs tunnel calls) so `stepOut` knows where to stop. `env` is restored on step-out. Only function/knot entries create a new env scope; gather/inline frames share the parent env.

**outputBuffer.buffer** — mixed array of strings and instruction tables (`{glue=true}`, `{nl=true}`, `{trim=true}`, `{trimEnd=true}`, `{outBlockStart=true}`, `{outBlockEnd=true}`). `outputBuffer:collect()` processes these into clean lines via a multi-pass pipeline.

**AST nodes** — all carry `.type` and `.location = {source, line, col}`. Named fields only. Key node types: `ink`, `knot`, `stitch`, `fndef`, `option`, `gather`, `choice`, `seq`, `if`, `out`, `divert`, `call`, `ref`, `var`, `const`, `tempvar`, `assign`, `return`, `tag`, `listdef`, `listlit`, `el`.

**Runtime value types**: `int`, `float`, `bool`, `str`, `list`, `el`, `fn`, `native`, `external`, `divert`.
